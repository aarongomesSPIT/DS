Details/Theory :
A Hash Table is a linear data structure that stores data as key–value pairs and provides efficient insertion,
deletion, and search operations. It uses a hash function to compute an index (hash value) from a given key,
allowing records to be accessed directly instead of searching sequentially.
The performance of a hash table depends on the quality of the hash function, which should distribute keys
uniformly across the table to minimize collisions. The average time complexity for insertion, deletion, and
search operations is O(1), whereas the worst-case complexity is O(n) when excessive collisions occur.
A collision occurs when two or more keys map to the same hash table index. Common collision resolution
techniques include Separate Chaining, Linear Probing, Quadratic Probing, and Double Hashing.

Application Perspective
Social media platforms and online services require every username to be unique. Whenever a new user
registers, the system must quickly determine whether the requested username already exists. Searching
sequentially through millions of user records is computationally expensive and leads to poor user experience.
Hash Tables enable efficient username lookup with average O(1) search complexity, making them suitable for
real-time username availability checking. This experiment demonstrates how hashing supports fast
registration and efficient management of unique usernames while resolving collisions effectively.
